# Contracts

On-chain verification for the ZK Proof Lab's `range_proof` circuit.

## `Verifier.sol` — generated, do not hand-edit

`Verifier.sol` is a Solidity verifier **generated by Barretenberg** for the
compiled `range_proof` circuit. It is machine-generated (~100 KB); never edit it
by hand — regenerate it instead.

### How it was generated

Requires the `bb` CLI (**v5.1.0**, matching `@aztec/bb.js` in `package.json`) and
the compiled circuit at `circuits/range_proof/target/range_proof.json`:

```bash
# 1. Verification key — target MUST be `evm` (keccak, ZK) to match the
#    `verifierTarget: "evm"` used in src/lib/circuits/proof.ts.
bb write_vk \
  -b circuits/range_proof/target/range_proof.json \
  -o circuits/range_proof/target/vk \
  -t evm --output_format binary

# 2. Solidity verifier from that VK, same target.
bb write_solidity_verifier \
  -k circuits/range_proof/target/vk/vk \
  -o contracts/Verifier.sol \
  -t evm
```

The `-t evm` target is load-bearing: a proof produced with any other
`verifierTarget` will **not** verify against this contract, and vice-versa.

Provenance is checkable: the `VK_HASH` constant near the top of `Verifier.sol`
equals the committed `circuits/range_proof/target/vk/vk_hash`.

### Facts the rest of the app depends on

- **Solidity contract:** `HonkVerifier` (a `ZK Honk` verifier).
- **Interface to call:**
  `function verify(bytes calldata proof, bytes32[] calldata publicInputs) external view returns (bool)`
- **Public inputs:** `NUMBER_OF_PUBLIC_INPUTS = 10`. The circuit declares 2
  public inputs (`min`, `max`); UltraHonk-ZK appends more (pairing-point
  accumulator). The `publicInputs` array passed on-chain must account for this —
  it is not simply `[min, max]`. (Wiring the exact split is handled where the
  proof is submitted on-chain.)
- **Compiler:** needs **solc ≥ 0.8.27** (the file carries a `^0.8.27` pragma).
  Verified to compile with solc 0.8.28 + optimizer.
